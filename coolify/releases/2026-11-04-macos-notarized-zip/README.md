# Mac notarized ZIP website release

Root owns certificate approval, Apple submission, actual signed-app/ticket/Gatekeeper checks, immutable ZIP acceptance, Git, host execution and publication. These helpers never create signing credentials, submit to Apple, alter API/database/native binaries, prune Docker or remove existing downloads.

The exact current web base is `flixify-ops-web:qr-device-login-20cad131f98f-20261103`, image `sha256:af9e74473b7ea55e077a3cbb5c8ce3aa3f302e0cb58e4cc16fb91df25228e437`. Canonical source base is `f820673242b543f849eb2bee2e1e9c48eef10971`. The only allowed production website delta is `app/platform/mac-download.ts`, `app/indir/page.tsx`, and one added ZIP under `public/downloads/`. Native packaging scripts can change independently; this release never copies them into the running website.

After actual Apple acceptance, root writes an independent artifact pin JSON containing exactly `path`, `sha256` and `bytes`. No sample digest or approval booleans are provided. The builder requires the immutable Git ZIP to match these pins, its descriptor to match the same filename/digest/size and `notarized: true`, and the path to be absent in both canonical and actual baselines. The old public manifest is retained byte-for-byte with only that ZIP added. Source merging uses unique exact anchors and retains actual operational changes outside the reviewed hunks.

Invoke `build-web.py REPO --revision FULL_COMMIT --artifact-pin PIN.json --measure` first, inspect the returned untouched-source fingerprint, and save it to a private source-pin JSON. Then pass `--source-pin SOURCE.json` to the default read-only preflight, `--build`, or `--verify-existing`. A real build requires 5 GiB free, runs offline at 1 CPU/1280 MiB RAM/1536 MiB total memory and swap/256 processes, disables Next's disk cache only while compiling, restores the original Next config, and commits normally on the one-layer base. It does not flatten or duplicate the whole root filesystem. Candidate verification includes all Config keys apart from Docker's transient compiler Hostname/Image bookkeeping, public build settings, every owned file, untouched runtime/dependency fingerprint, and every old public byte. Existing containers and images must remain intact.

After root reviews the build receipt, invoke `release.py --revision FULL_COMMIT --candidate-id sha256:...` for read-only release preflight. `--apply` synchronizes only the web image in Coolify's records and Compose; `--recreate` performs the guarded `--no-build --pull never` web-only cutover. Both require 4 GiB free. The existing shared release lock serializes these operations. API, worker, database, environment, registration fence, and other project containers remain protected by immutable pins and state fingerprints. A failed cutover verifies its recovery context and restores only the previous QR-enabled web image. Explicit `--rollback` uses the same verified recovery and is deliberately allowed below the forward disk floor. No QR sessions are revoked because the API is unchanged.

This is prepared source, not a claim of actual host build, cutover or public acceptance. Root must record the real phase results and validate canonical HTTPS pages plus ZIP HEAD/range/full-download hashes after publication.
