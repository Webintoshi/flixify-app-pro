# Single and dual user package sales

Requested catalog: 1, 6 and 12 months only. Single-device totals are 250, 699 and 999 TRY. Two-device totals are 399, 999 and 1,399 TRY. Dual means the same account code can play on two devices simultaneously.

New purchases use one-time card payments embedded in the website, without automatic renewal. A three-card selector follows the supplied pricing component while retaining the existing Flixify theme and CSS Modules. The switch changes the capacity, actual package slug and all three totals together. Card purchase is offered only when the API confirms the exact catalog amount, duration and capacity. Manual payment keeps the selected six-way slug.

Keep the existing single-plan IDs and retire only new sales of `3-ay`. Preserve its historical payments and entitlements. The dual slugs end in `-2-kullanici`. Provider package IDs are 8/10/11 for single and 13/15/16 for dual. Annual provider durations use years and must normalize to 12 months. Provider readback must confirm the exact line, expiry and connection capacity before access is granted. Worker synchronization must retain that distinction on renewal.

Legacy Stripe subscriptions and invoice processing remain separate from new one-time payment jobs. New sales do not create recurring subscriptions. Browser completion and return URLs are never proof of paid access. Ambiguous provider writes require review instead of blind retry.

All publication images start from the current immutable images and retain production-only code, dependencies, environment, APK files and registration ledgers. Compile offline in bounded owned containers. Do not prune shared Docker data or restart unrelated projects. No real card charge or provider playback is needed for verification.

Verification evidence is stored outside the repository in `work/artifacts/packages-20261101`. Catalog fixtures preserve existing IDs, accounts, payment references and row security, and apply idempotently. Real isolated PostgreSQL tests cover atomic failure and repeated dual-capacity renewal. Browser checks cover the switch and mobile overflow; embedded-payment tests cover submission, initialization, polling failure and cleanup.
