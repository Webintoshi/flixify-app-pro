# Android TV cache and responsiveness repair

The existing 1.4.4 client already has metadata/artwork caches, but cold catalog rendering waits for remote library data, favorites performs repeated full scans, and live curation can run under the UI-visible repository lock. Movie playback also forces full catalogue downloads. The owner reports severe slowness and several unexplained process exits after an in-app upgrade. No device crash trace is available, so do not claim a particular crash cause until reproduced.

Use the current native Java client and private, bounded device cache. Store compact source/account/expiry-scoped library references and resolved favorite metadata alongside streamed catalogue snapshots. Show usable cached metadata after current bootstrap, refresh quietly, and warm unvisited catalogue kinds while idle or an update is being prepared. Do not download video or every poster. Warm only the modest visible/nearby artwork window. Keep all access deadlines, source/policy checks, provider credentials memory-only, general-audience movie filter, colors, remote/player behavior and signing identity.

Approaches considered: server Redis/Dragonfly would not remove local lock/scan/JSON allocation pressure or provider calls from the viewer IP. Bundling the full user catalogue/artwork in the APK increases download size and exposes stale/account-specific data. The chosen repair uses small private snapshots plus optional background metadata work without adding server dependencies.

Move expensive projection off callback/main thread and outside long-held shared locks; callbacks still fence auth/source/policy/expiry at delivery. Avoid full JSON byte/string/tree copies by streaming provider catalogue arrays row by row. Read/write disk payloads with bounded buffers while retaining old cache compatibility. Cancel retired artwork queues/connections without blocking the UI; trim RAM on device pressure.

Publish 1.4.5/code13 with the existing package and certificate, unchanged Android6 floor and target35. Preserve old immutable APKs, Play Protect/security settings and every unrelated production source/service. Verify host JVM + actual Android cache/race/large catalogue tests, optimized release lint, same-signer update with retained private cache/session files, cold launch and guarded static APK publication. Emulator evidence does not prove every physical TV or diagnose the user's specific crash.
