# Windows player parity audit

Mode: AFTER, selected for this session. This audit records the completed player UI changes and the evidence available at review time. No further design changes were made during the audit.

Reading this as: Flixify's desktop video player for existing subscribers, using the established native macOS player layout and palette, ENERGY 1 / RHYTHM 1 / MOTION 1. Video remains the focal point; the controls appear around its edges when needed.

## Direction and purpose

- Layout: reproduce `apps/macos-native/Sources/FlixifyMac/Player/PlayerScreen.swift`. A close button sits 24 logical pixels from the top-left; the title is bottom-left; compact tools are bottom-right.
- Typography: use the platform's Segoe UI on Windows, with the same 23/13/12-pixel title, metadata and time hierarchy. This preserves legibility without introducing another typeface.
- Palette: white controls over black video scrims; Flixify red is reserved for favorites, the live indicator and the playing episode. The white seek and volume sliders match the macOS player.
- Buttons and spacing: 36-pixel square tools, 10-pixel corner radius, 8-pixel tool gaps, a 65-pixel volume slider, 28-pixel footer side margins and 24-pixel footer bottom margin reproduce the source hierarchy.
- Icons: dedicated vector close, heart, next episode, speaker, waveform, captions, episodes, calendar, settings and fullscreen symbols identify the same actions as the macOS source. They replace font-dependent Unicode characters and text labels.
- Panels: existing audio/subtitle APIs, verified series data, EPG data and the player rate/aspect APIs back the controls. The dark panel fill separates choices from video; the border marks their extent.
- Motion and input: no decorative animation was added. Existing pointer deduplication, single/double click separation, keyboard focus ownership and temporary control holds remain in place.

## Findings

No additional actionable design finding was identified in the rendered Qt preview. The former top title/favorite row, textual back button, oversized controls, VOD play/seek strip, red timeline and textual audio/subtitle/episode actions have been replaced with the requested macOS hierarchy.

Native Windows video and physical input verification remain required before release under R-35. The local macOS Qt preview deliberately reports `passed: false` and `localMediaPlaying: false`, because it has no Windows VLC runtime. Its successful UI checks must not be described as native Windows playback proof.

Apple's SF Symbols, system font rasterization and ultra-thin material are platform-specific. Windows uses explicit vector equivalents, Segoe UI and a dark translucent panel surface; pixel-identical Apple rendering is not claimed.
